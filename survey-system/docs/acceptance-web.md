# 手工测试步骤（第一阶段验收）

本文是一份**可独立执行**的验收清单：按顺序操作、逐条核对预期结果，即可复现第一阶段的
全部用户可见行为。读者不需要阅读代码或直接查询数据库。

- 步骤编号（A1、C2…）用于回报结果，请按编号记录「通过 / 失败」。
- 每一步都给出「操作」与「预期」。
- 命令以 Windows + Git Bash 为准；其他环境请自行调整路径写法。

---

## 0. 环境准备

### 0.1 启动 MongoDB

本项目使用**独立的数据目录**，不与其他 MongoDB 数据混用：

```bash
# 若 mongod 不在 PATH 中，改用完整路径，例如 "<MongoDB 安装目录>/bin/mongod.exe"
mongod --dbpath "<仓库根>/.mongodb/data" \
       --logpath "<仓库根>/.mongodb/mongod.log" \
       --port 27017 --bind_ip 127.0.0.1
```

目录不存在时先创建：`mkdir -p "<仓库根>/.mongodb/data"`。

验证（`mongosh` 同理，不在 PATH 时用完整路径）：

```bash
mongosh --quiet --eval "db.adminCommand({ping:1})"
# 预期：{ ok: 1 }
```

### 0.2 启动应用

```bash
cd <仓库根>/survey-system
python -m venv .venv                                      # 仅首次
.venv/Scripts/python -m pip install -r requirements.txt    # 仅首次
.venv/Scripts/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

启动成功的标志：日志出现 `Application startup complete`。

### 0.3 打开页面

浏览器访问 <http://127.0.0.1:8000/>。下文所有路径都基于该地址。

## 1. 测试前置约定

1. **使用全新的用户名。** 若数据库里已有数据，重复使用旧用户名会触发「用户名已被占用」。
   本文示例用 `qa_owner`（创建者）、`qa_fill`、`qa_fill2`（填写者）。
2. **创建者与填写者必须使用两个独立的浏览器上下文**（无痕窗口或不同浏览器 profile），
   否则会话 Cookie 会互相覆盖。
3. 前一轮测试留下的同名问卷不影响本轮；问卷以各账号自己的列表为准。

## 2. 测试步骤

### A. 注册与登录

| 编号 | 操作 | 预期 |
|---|---|---|
| A1 | 打开 <http://127.0.0.1:8000/> | 未登录，自动跳转到登录页 `/login`；页面为中文，含「用户名」「密码」标签与「注册新账号」链接 |
| A2 | 点「注册新账号」，进入 `/register` | 显示中文注册表单：用户名、密码、注册按钮 |
| A3 | 用户名 `qa_owner`，密码 `secret123`，点「注册」 | 注册成功，回到 `/login` |
| A4 | 用 `qa_owner` 再注册一次 | 页面红字提示 **「用户名已被占用」**，不创建 |
| A5 | 用 `qa_owner` + 错误密码 `wrongpass` 登录 | 提示 **「用户名或密码错误」**，不进入系统 |
| A6 | 用 `qa_owner` / `secret123` 登录 | 进入「我的问卷」`/surveys`；页头显示 `qa_owner` 与「退出」 |
| A7 | 点「退出」 | 回到登录页；之后再访问 `/surveys` 仍要求登录 |

### B. 新建问卷草稿

| 编号 | 操作 | 预期 |
|---|---|---|
| B1 | 在「我的问卷」页点「新建问卷」 | 进入 `/surveys/new` |
| B2 | 标题留空直接提交 | 提示 **「请填写问卷标题」**，不创建 |
| B3 | 标题填 `数据库课程问卷`，说明填 `第一阶段验收演示`，提交 | 回到 `/surveys`，列表出现该问卷，状态为 **「草稿」** |
| B4 | 点该问卷的「管理 / 查看」 | 进入编辑页 `/surveys/{id}/edit`，显示「添加题目」表单 |

### C. 四种题型与限制配置

在编辑页的「添加题目」表单里依次添加。**C1 与 C5 是本轮重点**（选项数量）。

| 编号 | 操作 | 预期 |
|---|---|---|
| C1 | 题型「单选题」，题干 `你平时使用哪种数据库？`，勾「必答」；表单默认给出 **2 个**选项输入框，填「关系型数据库」「文档数据库」；**点「添加选项」按钮**，应多出第 3 行，填「图数据库」；提交 | 第 1 题出现，标注「（必答）」，列出 **3 个**选项 |
| C2 | 题型「多选题」，题干 `你了解哪些 MongoDB 特性？`，勾「必答」；选项「副本集」「分片」「聚合管道」；「最少选择数」填 `1`；提交 | 第 2 题出现，标注「（必答）」，限制为最少 1 项 |
| C3 | 题型「数字题」，题干 `你每周投入学习多少小时？`，勾「必答」；最小值 `0`，最大值 `168`，勾「只接受整数」；提交 | 第 3 题出现，标注「（必答）」 |
| C4 | 题型「文本题」，题干 `补充说明（选填）`；「最多字数」填 `20`；提交 | 第 4 题出现，**不**标「必答」 |
| C5 | 回到第 1 题的编辑表单，点「添加选项」追加一行填「其他」并保存 | 第 1 题选项变为 **4 个**；原有三个选项的文字与顺序不变 |
| C6 | 把新增的「其他」一行**清空**后保存 | 空行被丢弃，选项回到 **3 个**，不出现空选项 |
| C7 | 对第 2 题重复一次「添加选项」再清空 | 行为与 C5/C6 一致 |

### D. 跳转规则

| 编号 | 操作 | 预期 |
|---|---|---|
| D1 | 第 1 题的「跳转规则」：目标选「第 3 题」，条件选「关系型数据库」，保存 | 页面回显：目标仍为第 3 题，条件仍为「关系型数据库」 |
| D2 | 第 1 题再加一条规则：条件选「图数据库」，目标选「结束（进入确认页）」，保存 | 第 1 题下出现 **2 条**规则，按保存顺序排列 |
| D3 | 点第二条规则的「上移规则」 | 两条规则顺序互换 |
| D4 | 对第一条规则点「下移规则」 | 顺序换回原样 |
| D5 | 对第一条规则再点「上移规则」 | 已在首位，顺序**不变**，无报错 |

### E. 发布

| 编号 | 操作 | 预期 |
|---|---|---|
| E1 | 在编辑页点「去发布」，进入 `/surveys/{id}/publish` | 显示发布确认页，含匿名与重复填写选项 |
| E2 | 勾选「匿名填写」，**不勾**「允许同一账号重复填写」，点「发布问卷」 | 回到编辑页，状态变为 **「已发布」**，页面顶部出现可分发的填写链接 `/s/{id}` |
| E3 | 记录完整的 `/s/{id}` 地址 | —— |
| E4 | 尝试再修改第 1 题 | 被拒绝，提示问卷已发布、题目与选项已冻结 |

### F. 登录返回与填写校验

**以下在无痕窗口中操作。**

| 编号 | 操作 | 预期 |
|---|---|---|
| F1 | 无痕窗口访问 `http://127.0.0.1:8000/s/{id}` | 跳转登录页，地址栏带 **`?next=/s/{id}`** |
| F2 | 在该窗口注册 `qa_fill` / `secret123` 并登录 | 登录成功后**自动回到** `/s/{id}`，而不是「我的问卷」 |
| F3 | 第 1 题选「文档数据库」；第 2 题**一个都不选**；第 3 题填 `5`；第 4 题留空；点「下一步」 | 第 2 题下方红字提示 **「…为必答题，请至少选择一项」**；已填内容保留 |
| F4 | 第 2 题选「副本集」；第 3 题改成 `999`；点「下一步」 | 第 3 题下方红字提示 **不能大于 168** |
| F5 | 第 3 题改回 `5`；第 4 题填 `第一阶段`；点「下一步」 | 进入**确认提交**页，逐条列出四题的回答 |
| F6 | 点「返回修改」，把第 4 题改到 **21 个字以上**，再提交 | 提示超过最多字数（20），不进入确认页 |

### G. 返回修改与确认提交

| 编号 | 操作 | 预期 |
|---|---|---|
| G1 | 在确认页点「返回修改」 | 回到填写页，各题答案**全部回填**（第 1 题「文档数据库」仍选中、第 4 题文本仍在） |
| G2 | 把第 4 题改回 `第一阶段`，点「下一步」回到确认页，点「确认提交」 | 进入**提交成功**页，提示答卷已保存 |

## 4. 判定标准

- **通过**：实际观察与「预期」一致，且没有额外报错。
- **失败**：与预期不符、出现 5xx 错误、页面无响应，或产生了预期外的数据。
- **无法执行**：因环境问题（如 MongoDB 未启动）导致整段无法进行，需单独说明，**不计为通过**。

> 不要把「环境没起来」记成功能失败；也不要把「没检查到」记成通过。

## 5. 已知限制（不要误判为缺陷）

- 会话 Cookie 为 `SameSite=Lax`；**同一浏览器**里换账号会覆盖会话，务必用无痕窗口区分。
- 网页上的截止时间按**服务器本地时区**解释后折算 UTC；多时区部署时需改为客户端提交时区偏移。
- 关闭是**终态**，第一阶段不提供重新开放。
- 发布后标题、说明、题目、选项、跳转规则与匿名 / 重复配置均**冻结**，只允许调整截止时间或关闭。
- 已提交的答卷**不提供修改**；第一阶段不做跨设备填写草稿。
- 统计接口与页面目前也允许查看**草稿**问卷（返回空统计），这是有意保留的行为。
- 填写页的前端跳转只是体验增强，**服务端始终从第一题重算有效路径**；若前端隐藏的题目与实际不符，以提交后确认页与服务端结果为准。

## 6. 与自动测试的关系

- 接口行为由自动测试覆盖（208 例），见 `docs/test-record.md`。
- 本文覆盖**浏览器交互**，两者互补：接口测试不能代替浏览器交互验收，浏览器步骤也不替代回归测试。
- 使用 Playwright / Selenium 等驱动真实浏览器时，**必须用真实控件交互**（点击、键入、提交表单），不要用直接构造 HTTP 请求代替，否则测不到本文要验证的界面行为。
