## 3. 规格、拆分与实现（2026-10-16 21:16 起）

### 3.1 规格与拆分获批，以及一次**偏离后被纠正**

- AI 生成 `spec.md`（30 条用户故事 + 技术方案 + 测试范围）与 `ticket-proposal.md`
  （7 项拆分及依赖），先标 draft。
- **人工决策**：用户批准规格与 7 项拆分，确认测试入口为“HTTP 接口 + 真实隔离
  MongoDB”，同意照草案的保守默认值执行（21:16 记录为草案，23:01 记录为批准）。
- **AI 的一次错误（被主控指出）**：AI 起初在**当前目录顺序实现**，偏离了原版
  implement-spec 编排。主控当时直接质问实现是否严格遵循技能说明，AI 才回头核对原文，
  确认偏离成立。

- AI 对照 `implement-spec/SKILL.md` 与 `matt-development-flow/SKILL.md` **原文**核对，
  确认偏离成立（宿主可派子 agent、项目可用 worktree，原执行条件成立），并承认另有两
  处偏差：未按 `tdd` 要求先确认接缝、未跑 update-scope 记录进展。
- **人工决策**：主控选择改按原版编排 → AI 建集成分支
  `integration/mongodb-survey-phase-one`，改为“implementer 子 agent 在独立 worktree
  实现（各自调用 tdd）→ merger 子 agent 合入集成分支 → 全部完成后在集成分支跑
  code-review”。

## 8. 总结

第一阶段是“人定规则、AI 落地”的协作：**业务规则与关键取舍由用户拍板**，AI 负责
澄清、生成规格与代码、写测试、维护记录。过程中 AI 出现过一次实质偏差（偏离原版
编排），被主控指出后按原文核对并纠正为“集成分支 + 子 agent + worktree”编排；并行
开发暴露出测试库互冲与 03/05 合并冲突两个真实问题，均通过提交（`cbfeefe`、`b816ec4`）
解决了。全过程 AI 未预填通过结果、未伪造审查；无法还原的信息按上文标为未记录。
