# MongoDB 问卷系统 · 第一阶段项目报告

本报告把第一阶段的代码、建模、设计、接口、测试与真实 AI 使用过程串成一份可交的
总览。细节分散在各分册，本报告给出结论并指向来源。

- 分册：`docs/mongodb-schema.md`（建模）、`docs/design.md`（系统与数据库设计）、
  `docs/api.md`（接口与关键逻辑）、`docs/configuration.md`（配置与启动）、
  `docs/acceptance-web.md`（网页验收步骤）、`docs/test-record.md`（测试真实结果）、
  `docs/ai-usage-log.md`（AI 使用日志）。
- 决策记录：`docs/adr/0001`（生命周期与截止时间）、`docs/adr/0002`（内嵌与部分唯一索引）。

## 1. 目标与范围

第一阶段交付一个**本机运行**的中文问卷系统：注册登录、私有问卷管理、四种题型与
限制校验、可配置条件跳转与返回修改、匿名、防重复提交、截止与关闭、问卷级与题目级
统计。业务数据全部存于 MongoDB。成果须能在第二阶段继续扩展，不推倒重做。

不在范围内：公网部署、现成问卷框架、关系数据库、管理员后台、密码找回、邮件通知、
模板、导入导出、图表美化、提交后编辑、跨设备草稿。

## 2. 技术选型

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 语言 / 运行时 | Python 3.12 | 本机可用；生态成熟 |
| Web 框架 | FastAPI | 自带 OpenAPI 文档，便于按接口验收 |
| 数据库驱动 | PyMongo | MongoDB 官方驱动 |
| 前端 | 后端同源渲染的 Jinja2 模板 + 原生 HTML/CSS/JS | 无前端构建流程，降低复杂度 |
| 数据库 | MongoDB 9.0.2（本机 127.0.0.1:27017） | 课程硬性要求 |
| 密码哈希 | 标准库 `hashlib.pbkdf2_hmac` | 不额外引入哈希库 |
| 测试 | pytest + httpx（经 FastAPI TestClient） | 以 HTTP 接口为主要测试入口 |

依赖固定在 `survey-system/requirements.txt`，未新增第三方依赖。

## 3. 架构总览

单进程 FastAPI 应用，同源提供 JSON 接口与中文网页；无队列、无缓存、无后台服务。
分层：路由层（`app/main.py`）→ 领域层（`surveys` / `questions` / `responses` / `stats`）
→ 基础设施（`db` / `security` / `sessions` / `csrf`）→ MongoDB。详见 `docs/design.md`。

## 4. 数据建模要点

- 四个集合：`users`、`sessions`、`surveys`、`responses`。
- 题目、选项、规则**内嵌**进 `surveys`（整体读写、整体冻结、无独立生命周期），用
  稳定标识 `qid`/`oid`/`rid` 做引用而非显示下标。
- 答卷独立成集合、只增不改；禁止重复用 `(survey_id, respondent)` 的**部分唯一索引**
  （`partialFilterExpression: {once: true}`）在数据库层拦并发，不靠先查后写。
- 完整字段、索引与取舍理由见 `docs/mongodb-schema.md` 与 `docs/adr/0002`。

## 5. 功能实现清单（对应 7 项交付）

| 工单 | 交付 | 关键实现 |
| --- | --- | --- |
| 01 | 注册登录、私有草稿、最小可运行与隔离测试环境 | `security`/`sessions`/`surveys`，唯一索引保证用户名、令牌唯一 |
| 02 | 单选问卷发布、填写、提交、匿名与防重复 | `questions`/`responses`，部分唯一索引防并发重复 |
| 03 | 多选、文本、数字题型与完整限制校验 | `questions._clean_limits`、`responses._validate_*`，发布校验拒绝矛盾配置 |
| 04 | 条件跳转与返回修改、失效答案清理 | `compute_path` 从第一题重算有效路径，路径外答案剔除 |
| 05 | 截止时间与手动关闭 | `deadline`（UTC）+ `status=closed` 终态，提交前再次核验（ADR 0001） |
| 06 | 问卷级与题目级统计 | `stats`，按成功答卷的有效答案汇总，匿名不泄露身份 |
| 07 | 完整演示、回归、课程交付 | 本文档集 + 真实回归与网页验收记录 |

## 7. AI 使用过程（摘要）

第一阶段由 AI 主导生成规格、代码与测试，业务规则与关键取舍由用户拍板；过程中 AI
出现过一次实质偏差（偏离原版实现编排）并被主控指出后按原文纠正，并行开发暴露了测试
库互冲与工单 03/05 合并冲突两个真实问题并已解决。完整、带来源与“未记录”标注的日志
见 `docs/ai-usage-log.md`。

## 8. 已知限制与第二阶段可扩展点

- **保留的第一阶段基线**：`survey-system/` 的代码结构、MongoDB 集合与字段、`README`
  与 200 例测试全部保留，第二阶段可在其上扩展，不需推倒重做。
- 已知限制（可作第二阶段入口）：
  - 统计查询没有单独的 `survey_id` 索引（当前规模不构成问题）；
  - 会话过期靠应用判断，未用 TTL 索引；
  - 网页截止时间的本地时间折算依赖服务器时区（多时区部署需改为客户端提交偏移）；
  - 发布后内容冻结是产品决策；关闭为终态、无重开；
  - 「我的问卷」列表在本 ticket 前缺少进入编辑页的链接，已修复。

```bash
SURVEY_TEST_DB_NAME=survey_test_xxx .venv/Scripts/python -m pytest -q   # 回归
```
