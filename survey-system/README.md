# 问卷系统（第一阶段）

创建、填写问卷并统计结果的中文网页系统。业务数据全部存储于 MongoDB。
本阶段已实现账号注册登录、退出，私有问卷草稿的创建、查看与修改，单选、多选、
文本、数字四种题型的添加、编辑与限制配置，单选 / 多选 / 数字题的**条件跳转规则**
与顺序调整，问卷发布与分发链接，多题型问卷**按有效路径**的填写与提交（含按题型的
服务端校验、返回修改与失效答案清理、匿名与重复限制），以及截止时间设置与手动关闭问卷。

## 发布流程与访问链接

1. 创建者在草稿编辑页 `/surveys/{id}/edit` 逐题添加题目（单选 / 多选 / 文本 / 数字），勾选必答并设置各题型限制；选择题可点「添加选项」追加选项行（数量不设前端上限，编辑已有题目时同理，空白行提交时忽略）；可上移 / 下移排序，或删除题目。
2. 进入发布确认页 `/surveys/{id}/publish`，勾选匿名填写与是否允许重复填写（默认非匿名、禁止重复），点击发布。
3. 发布时校验：至少一道题；每道题有题干；选择题至少两个选项；限制配置合法（见“题型与限制字段”）；跳转规则只向后跳或结束、条件引用仍存在（见“条件跳转规则与有效路径”）；不通过则拒绝并提示。
4. 发布成功后，问卷状态变为 `published`，编辑页展示可分发链接 `/s/{id}`。分享该链接即可。
5. 发布后标题、说明、题目、选项与匿名 / 重复配置都冻结，不能修改；仍可设置或调整截止时间，并可手动关闭问卷。
6. 填写者打开 `/s/{id}`：未登录先登录并回到该问卷；未发布的问卷打开提示未发布；逐题作答后进入确认页，确认后提交。匿名问卷在服务端移除填写者身份后才返回给创建者，但系统仍记录账号以限制重复。

## 问卷生命周期与截止时间

问卷状态为 `draft`（草稿）→ `published`（已发布）→ `closed`（已关闭）。关闭是终态，第一阶段不提供重新开放；草稿与已发布问卷可设置或清除截止时间，已关闭问卷不能再调整。

- **截止时间按 UTC 存储**：接口接受带时区偏移或 `Z` 的 ISO 8601（无时区按 UTC 解释），一律折算为 UTC 后存入 `surveys.deadline`；管理页显示与填写时按本地时间呈现（浏览器 `datetime-local` 提交的本地时间在服务端折算为 UTC 存储）。
- **截止瞬间视为不可提交**：判定用 `now >= deadline`（闭区间），截止时刻本身及之后一律拒绝。
- **提交前再次核验**：打开填写页与每次提交都重新读取问卷状态，核验是否已发布、是否已关闭、是否已截止。填写过程中问卷被关闭或被调整到已截止，后续提交仍会被拒绝（不是只在打开页面时检查一次）。
- **终态与拒绝口径**：已关闭或已截止的问卷，填写页与提交均返回 `409` 并给出中文提示（`问卷已关闭，不再接受答卷` / `问卷已截止，不再接受答卷`）；对已关闭问卷再次关闭、重新发布或改回草稿一律 `409`。非创建者调整截止时间或关闭问卷统一返回 `404`，不泄露问卷是否存在。

状态与截止时间存储约定见 [`docs/adr/0001-survey-lifecycle-and-deadline.md`](docs/adr/0001-survey-lifecycle-and-deadline.md)。

## 数据模型

- `users`：`username`（唯一）、`password_hash`、`created_at`
- `sessions`：`token`（唯一）、`username`、`created_at`、`expires_at`
- `surveys`：`owner`、`title`、`description`、`status`（`draft` / `published` / `closed`）、`config`（`anonymous` / `allow_multiple`）、`questions`（有序内嵌）、`deadline`（UTC 时间或 `null`）、`created_at`、`updated_at`、`published_at`、`closed_at`
- `surveys.questions[]`：`qid`（稳定标识）、`type`（`single` / `multi` / `text` / `number`）、`title`、`required`、`options[]`（仅选择题）、`rules[]`（跳转规则，仅单选 / 多选 / 数字），以及按题型的限制字段
- `surveys.questions[].options[]`：`oid`（稳定标识）、`text`
- `surveys.questions[].rules[]`：`rid`（稳定标识）、`condition`（按题型，见“条件跳转规则与有效路径”）、`target`（目标题目 `qid` 或 `end`）
- `responses`：`survey_id`、`respondent`（内部填写者账号）、`answers[]`（有效答案，形态见下）、`submitted_at`、`once`（仅在禁止重复时存在）

题目与选项使用稳定标识（`qid` / `oid`），规则与答卷都引用标识而非显示序号；排序只调整内嵌数组顺序，不改动标识。答卷独立增长，每次成功提交写一条 `responses`。

### 题型与限制字段

一道题由 `type` 决定题型，限制字段按题型生效；不属于该题型的限制字段在写入时被丢弃，避免脏数据混进题目。矛盾或非法的限制配置统一在**发布校验**时拒绝（草稿阶段只做单字段类型规整）。

| 题型 | `type` | 选项 | 限制字段 | 说明 |
| --- | --- | --- | --- | --- |
| 单选题 | `single` | `options`（发布时至少两个） | — | 只能选一个有效选项 |
| 多选题 | `multi` | `options`（发布时至少两个） | `min_choices`、`max_choices` | 最少 / 最多选择数；**固定数量用相同的上下限表达**（同一约束） |
| 文本题 | `text` | 无 | `min_length`、`max_length` | 最少 / 最多**字数，按字符计数**（不是字节） |
| 数字题 | `number` | 无 | `min_value`、`max_value`、`integer` | 范围含两端；只接收**有限**数值，**布尔值不算数字**；`integer` 为真时要求整数 |

发布校验对限制配置的判定：

- 多选题：`min_choices`、`max_choices` 不得为负；`min_choices` 不得大于 `max_choices`，也不得超过选项总数（否则无法满足）。
- 文本题：`min_length`、`max_length` 不得为负；`min_length` 不得大于 `max_length`。
- 数字题：`min_value` 不得大于 `max_value`。

提交时服务端按题型重新校验：

- 多选题：答案为**不重复的**有效选项集合，数量满足最少 / 最多 / 固定数量。
- 文本题：字数为 `len(文本)`，落在最少 / 最多之间。
- 数字题：解析为有限数值后校验范围与整数要求；布尔值、非数字文本、无穷或 NaN 一律拒绝。
- **可选题为空时不触发规则**（不记错误，也不计入有效答案）；必答题为空则拒绝并定位到该题。

`responses.answers[]` 的形态按题型区分：单选为 `{qid, oid}`，多选为 `{qid, oids: [...]}`，文本为 `{qid, text}`，数字为 `{qid, number}`。

## 条件跳转规则与有效路径

只有**单选、多选、数字题**可以配置条件跳转；文本题不参与跳转。规则内嵌在题目上（`rules`），引用题目与选项的稳定标识（`qid` / `oid`），不引用显示序号。

### 规则语义

- **顺序即优先级**：同一题的规则按创建者排列的**从上到下顺序**逐条判断，**第一条命中生效**；都不命中则**进入下一题**；最后一题之后进入提交确认页。
- **调整顺序**：编辑页每条已保存的规则下有“上移规则 / 下移规则”按钮，点击即交换相邻两条规则的顺序；调整后按新顺序生效。
- **只可向后跳**：规则目标只能是本问卷中位于该题**之后**的题目，或**结束**（`end`）。不允许回跳，也不允许形成循环；这类规则在**发布校验**时被拒绝（见下）。
- **可选题为空不触发**：某题留空（或数字题未填）时不会命中任何条件，按默认进入下一题。
- **跳转到结束**只进入提交确认页（`/s/{id}` 的预览页），**不自动提交**；须在确认页再次确认。
- **被跳过的必答题无需填写**：必答只在有效路径上校验。

条件形态（按题型）：

| 题型 | 条件 `condition` | 含义 |
| --- | --- | --- |
| 单选 | `{"op": "is", "oid": <oid>}` | 选中指定选项 |
| 多选 | `{"op": "any", "oids": [...]}` | 包含**任一**指定选项 |
| 多选 | `{"op": "all", "oids": [...]}` | 包含**全部**指定选项 |
| 数字 | `{"op": "eq" \| "gt" \| "lt", "value": <数值>}` | 等于 / 大于 / 小于 |
| 数字 | `{"op": "between", "min": <数值>, "max": <数值>}` | 含两端的闭区间 |

一条规则形如 `{"rid": "r_...", "condition": {...}, "target": "<qid>" | "end"}`；`rid` 是规则自身的稳定标识，`target` 是目标题目 qid 或 `end`。

### 有效路径与失效答案清理

- **服务端从第一题重算有效路径**：提交时按每题命中的规则从第一题推进，**不信任客户端声称的路径**；只校验**路径上的题目**，必答与各题型限制也只在路径上生效。
- **不在有效路径上的答案被忽略并剔除**：即使客户端提交了本应被跳过的题的答案，也不会被校验，更不会进入答卷（不提交、不保存）。
- **允许返回已答题修改**：确认页可“返回修改”回到填写页并回填已填答案。**路径改变后，新路径不再经过的答案会被清除**——提交时以重算的路径为准，这些答案既不提交也不保存。
- **发布校验拒绝回跳与循环**：`_validate_rules` 要求每条规则的目标位于该题之后或为结束，因此回跳与循环一并被拒绝；同时拒绝指向已删除题目、或引用已删除选项的规则。

### 索引说明

| 集合 | 索引 | 用途 |
| --- | --- | --- |
| `users` | `username`（唯一） | 用户名唯一 |
| `sessions` | `token`（唯一） | 会话令牌唯一 |
| `responses` | `(survey_id, respondent)`（唯一，部分索引） | 禁止重复时同账号并发提交最多成功一次 |

`responses` 的唯一索引带部分过滤条件 `{"once": true}`：只有禁止重复的答卷带 `once` 标记（允许重复的答卷不带此字段），因此进入唯一索引的答卷保证同账号每问卷最多一条，而允许重复时同一账号可提交多份且互不覆盖。并发提交靠数据库唯一约束拦截，不依赖"先查后写"。

## 统计

创建者可在管理页进入统计页（`/surveys/{id}/stats`），查看问卷级汇总；也可从汇总页的“查看该题统计”进入题目级视图（`/surveys/{id}/stats/{qid}`）。接口为 `GET /api/surveys/{id}/stats`（问卷级）与 `GET /api/surveys/{id}/questions/{qid}/stats`（题目级）。统计只对问卷创建者开放：非创建者或不存在的问卷统一 `404`，未登录 `401`。

**统计口径**（哪些答案计入、空缺如何处理）：

- **只统计成功保存的答卷**：每次成功提交写一条 `responses` 文档；未提交、被拒绝的填写不产生答卷。
- **只统计有效答案**：被跳过的题、未填的可选题**不计为回答**。空文本不计为文本题回答；提交时路径外答案已被剔除，因此伪造的路径外答案也不进入统计。
- **数字无回答时平均值为空**：`average` 为 `null`，界面显示“暂无（无回答）”，**不显示为零**。
- **允许重复填写时每份答卷分别计数**：同一账号提交多份时，答卷数按文档逐份累加。

各题型统计字段：

| 题型 | 字段 | 说明 |
| --- | --- | --- |
| 单选 | `answered_total`、`options[]`（`oid` / `text` / `count`） | 各选项人数与有效回答总数 |
| 多选 | `answered_total`、`options[]`（`oid` / `text` / `count`） | 各选项被选择的次数；一份答卷里同一选项只计一次 |
| 文本 | `answered_total`、`texts[]` | 全部填空内容（空文本不计入） |
| 数字 | `answered_total`、`average`（无回答为 `null`） | 平均值 |

问卷级响应形如 `{"survey_id", "title", "response_count", "questions": [<逐题统计>]}`；题目级响应为单条题目统计 `{"qid", "type", "title", ...}`。

**匿名与越权隔离**：统计输出不含填写者身份（不输出 `respondent`），匿名问卷与非匿名问卷都不泄露填写者账号；非创建者不能查看统计。

## 安全说明

- 密码以标准库 `pbkdf2_hmac` 加盐哈希存储，任何接口都不返回密码或哈希。
- 会话使用不可预测的随机令牌，存放于服务端 MongoDB；客户端仅持有 HttpOnly、`SameSite=Lax` 的 Cookie，支持退出与过期（默认 7 天）。
- 登录失败对“用户名不存在”与“密码错误”返回同一文案，避免用户枚举。
- 网页表单写操作具备 CSRF 防护：服务端签发随机令牌（`app/csrf.py`），随页面渲染进表单隐藏字段并写入 `csrf_token` Cookie，提交时比较两者是否一致，不一致或缺失返回 403；配合会话 Cookie 的 `SameSite=Lax`。
- 用户提交的标题、说明、题干与选项等经 Jinja2 自动转义按文本显示，不执行 HTML，防止存储型 XSS。
- 匿名问卷的创建者响应在服务端移除填写者身份（`responses.py` 序列化时按 `anonymous` 决定是否输出 `respondent`），客户端隐藏字段不构成匿名保障；系统内部仍记录 `respondent` 以执行重复提交限制。
- 提交校验在服务端从第一题重算，不信任客户端提交的题目范围；未知题目一律忽略，按题型校验类型、大小与全部限制，必答为空、选项无效或数值越界都拒绝并定位到题目。
