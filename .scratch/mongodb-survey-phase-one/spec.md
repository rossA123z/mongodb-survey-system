# MongoDB 问卷系统第一阶段规格草案

Status: approved（2026-10-16 用户批准，可执行）

本规格根据课程需求和本次对话整理。已确认的业务规则与下文提出的实现方案分开记录。测试范围、技术方案与 7 项任务拆分已于 2026-10-16 获得用户批准，正式 tickets 见 `issues/`。

## Problem Statement

问卷创建者需要创建、发布和分发问卷，填写者需要按题目校验与可配置跳转完成填写，创建者需要统计结果。课程要求业务数据全部存储于 MongoDB，并展示建模、后端逻辑、测试、文档和真实 AI 使用过程。第一阶段成果须能在第二阶段继续扩展，不能推倒重做。

## Solution

提供中文网页，支持注册登录、问卷管理、逐题填写与结果统计。第一阶段在本机运行，以可复现说明交付，截止日期为 2026-10-23，具体截止时刻未提供。

已确认的规则：

- 填写必须登录。匿名指对创建者隐藏身份，系统仍可识别账号以限制重复填写。
- 是否允许重复填写由创建者配置，默认每账号每份问卷只允许一次成功提交。
- 发布后题目、选项和跳转规则冻结，仍可调整截止时间或关闭问卷。
- 规则只可跳向后面的题目或结束；跳过的必答题无需填写。
- 同一题规则按创建者排列顺序匹配，第一条命中生效，未命中进入下一题。
- 允许返回已答题修改；新路径不再经过的答案清除，不参与提交或统计。
- 跳转到结束进入提交确认页，不自动提交；提交前校验有效路径。
- 多选条件支持包含任一指定选项、包含全部指定选项；数字条件支持等于、大于、小于和含两端的区间。

## User Stories

1. 作为访客，我希望注册账号，以便创建和填写问卷。
2. 作为用户，我希望登录和退出，以便使用自己的账号。
3. 作为创建者，我希望只看到自己的问卷列表，以便管理自己的内容。
4. 作为创建者，我希望填写标题和说明，以便表达问卷目的。
5. 作为创建者，我希望配置匿名填写和重复填写，以便控制收集方式。
6. 作为创建者，我希望添加、编辑、删除和排序草稿题目，以便组织问卷。
7. 作为创建者，我希望设置单选题选项和必答要求，以便收集一个选择。
8. 作为创建者，我希望限制多选的最少、最多或固定选择数，以便约束回答。
9. 作为创建者，我希望限制文本最少和最多字数，以便收集适当长度的回答。
10. 作为创建者，我希望限制数字范围和是否整数，以便收集合法数值。
11. 作为创建者，我希望给单选、多选和数字题配置条件跳转，以便按回答分流。
12. 作为创建者，我希望调整规则顺序，以便确定多条命中时的结果。
13. 作为创建者，我希望发布前检查无效题目和规则，以便避免无法填写的问卷。
14. 作为创建者，我希望发布后获取问卷链接，以便分发给填写者。
15. 作为创建者，我希望设置和调整截止时间以及手动关闭，以便停止收集答卷。
16. 作为填写者，我希望打开链接后登录并回到该问卷，以便完成填写。
17. 作为填写者，我希望按顺序答题并按规则跳转，以便只回答适用的问题。
18. 作为填写者，我希望看到具体校验错误，以便修改答案后继续。
19. 作为填写者，我希望返回修改已答题，以便纠正错误。
20. 作为填写者，我希望结束时确认提交，以便避免误提交。
21. 作为填写者，我希望提交成功后答卷被保存，以便创建者收到结果。
22. 作为填写者，我希望明确得知问卷未发布、已关闭、已截止或不允许重复填写，以便理解不能提交的原因。
23. 作为匿名填写者，我希望创建者在答卷、统计和接口响应中均看不到我的账号身份，以便匿名参与。
24. 作为创建者，我希望查看单选各选项人数和有效回答总数，以便了解分布。
25. 作为创建者，我希望查看多选各选项选择次数，以便了解偏好。
26. 作为创建者，我希望查看填空内容和数字平均值，以便分析回答。
27. 作为创建者，我希望查看整个问卷或某道题的统计，以便集中分析。
28. 作为创建者，我希望多人同时填写时答卷不丢失，且重复限制始终有效，以便相信统计结果。
29. 作为验收者，我希望按说明启动、运行测试并复现演示，以便核验交付。
30. 作为课程提交者，我希望保留设计取舍、测试结果和真实 AI 使用记录，以便说明开发过程并支持第二阶段扩展。

## Implementation Decisions

以下为实现方案，待本草案确认。业务限制以上文已确认规则为准。

### 技术方案

- 使用 Python 3.12、FastAPI、PyMongo；前端使用同源 HTML/CSS/JavaScript，由后端提供，避免额外前端构建流程。
- 首选现有本机 MongoDB。实现前检查连通性，不修改用户已有数据库；配置数据库连接和独立的项目数据库名。
- 自动测试使用独立测试数据库，禁止清理业务数据库；版本依赖在实现时固定并记录。
- 单个应用按账号、问卷、填写校验/跳转和统计职责组织，不引入队列、缓存或微服务。

### 数据建模与一致性

- users 保存唯一用户名、密码哈希和注册时间；surveys 保存创建者、标题、说明、状态、截止时间、配置及内嵌的有序题目与规则；responses 每次成功提交一文档，保存问卷、内部填写者身份、有效答案和提交时间。
- 题目和选项使用稳定标识，规则引用标识而非显示序号；问卷整体读取、编辑，答卷独立增长。解释嵌入与引用、索引及 MongoDB 适用理由，不机械复制关系数据库表结构。
- 登录会话如需持久化也存 MongoDB；密码只存安全哈希，接口不返回密码哈希。
- 对禁止重复提交的问卷，用数据库唯一约束保证同账号并发提交最多成功一次；允许重复的提交互不覆盖。不能仅靠先查后写。
- 提交前再次核验问卷是否开放、截止、账号权限及有效路径；成功插入后返回明确结果。截止时间统一存 UTC，网页显示本地时间；截止瞬间视为不可提交。
- 默认设置建议：非匿名、禁止重复提交、无截止时间。发布后匿名及重复配置也冻结，避免前后答卷口径变化；关闭为终态，第一阶段不提供重开。
- 发布时校验题目、选项、限制及所有规则目标，至少存在一道题；冻结标题、说明和题目内容，允许修改截止时间及手动关闭。

### 账号和访问控制

- 会话采用安全随机令牌和 HttpOnly Cookie，支持退出与过期；同源写操作具备 CSRF 防护。普通用户不能读取或修改其他创建者的问卷管理内容与统计。
- 公开链接仅提供已发布问卷的填写入口，填写数据与统计不随链接公开；未登录先登录，再返回问卷。
- 匿名问卷的创建者响应在服务端移除填写者身份；客户端隐藏字段不构成匿名保障。非匿名问卷可展示填写者用户名。
- 用户提交内容按文本显示，避免执行 HTML；服务端校验类型、大小和所有输入限制，错误不得泄露内部凭据。

### 校验、跳转与统计

- 单选答案必须是一个有效选项；多选为不重复的有效选项集合，检查最少/最多/固定数量；文本按字符计数；数字只接收有限数值并检查范围与整数限制，不把布尔值视作数字。
- 可选题为空时不触发规则；有效回答仍需满足题型约束。固定多选数量与上下限统一为同一约束，拒绝矛盾配置。
- 单选条件为选中指定选项，多选条件为包含任一/全部指定选项，数字条件为等于/大于/小于/闭区间。首条命中生效，默认进入下一题，最后一题之后进入确认页。
- 前端及时反馈，服务端从第一题重算有效路径与校验。忽略并剔除不在有效路径上的答案，不信任客户端声称的路径。
- 返回修改后重新计算路径，清除失效答案；已提交答卷不提供修改。第一阶段不提供跨设备草稿恢复，仅成功提交形成持久答卷。
- 统计仅覆盖成功保存的答卷及有效答案；被跳过或未填的可选题不计为回答，空文本不参与平均值。数字无回答时平均值为空，不显示为零。允许重复时每份答卷分别计数。
- 公开填写入口与创建者管理入口都使用中文清晰提示，表单有标签、可用键盘操作，错误定位到具体题目。

## Testing Decisions

**待确认的测试范围：以 HTTP 接口作为主要自动测试入口，配真实 MongoDB；网页通过一套可复现的操作步骤验收。**

- 从注册、登录、创建、编辑、发布、填写、提交到统计验证完整行为，覆盖成功和拒绝路径；不测试私有函数的内部实现。
- 通过用户可调用的接口核验结果，使用隔离测试数据库；数据库约束的并发效果通过真实并发提交验证，不以 mock 代替。
- 必测：问卷与题目创建、四种题型、所有限制边界、三类跳转、规则优先级/默认路径/结束、失效答案清理、匿名、越权、重复提交与统计。
- 生命周期覆盖发布后内容冻结、截止边界、关闭后拒绝提交；验证无回答统计及多个账号同时提交。
- 页面验收覆盖中文表单、错误提示、规则配置、登录返回、返回修改、确认提交和统计展示。接口测试不能代替浏览器交互验收。
- 当前项目尚无应用代码和测试先例。每个 ticket 留下相关测试、真实结果和说明；不得预填通过结果。
- 交付前运行完整回归，独立审查，并形成测试步骤、输入、预期、实际输出和结论。

## Out of Scope

公网部署、现成问卷框架、关系数据库、管理员后台、密码找回、邮件通知、问卷模板、导入导出、图表美化、提交后编辑、跨设备填写草稿，以及第二阶段尚未发布的新需求。
