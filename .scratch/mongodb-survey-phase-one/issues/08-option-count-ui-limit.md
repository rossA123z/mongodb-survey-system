# 08 · 选择题选项数量的前端限制（缺陷）

Status: ready-for-agent
Blocked by: 无

## 现象

编辑页的「添加题目」表单只渲染 2 个选项输入框，且没有「添加选项」控件，因此**网页上无法创建含 3 个及以上选项的单选 / 多选题目**；编辑已有题目时同样只能修改现有选项的文字，不能新增选项行。

课程原始需求的单选示例（男 / 女 / 其他，共 3 个选项）与多选示例（4 个水果）在网页上**无法复现**。

## 定位证据

- `survey-system/app/templates/survey_edit.html:260-264` —— 新增题目表单固定渲染两个 `<input name="option">`，无增行控件。
- `survey-system/app/templates/survey_edit.html:200-208` —— 编辑已有题目时只遍历现有选项，无增行控件。
- `survey-system/app/main.py:722` —— `form.getlist("option")` 接收任意数量的选项，前端限制不属于后端契约。
- `survey-system/app/questions.py:54-56` —— 只有 `MIN_OPTIONS_AT_EDIT = 1`、`MIN_OPTIONS_TO_PUBLISH = 2`，**无上限校验**。
- `survey-system/app/main.py:748` —— 编辑提交用 `zip(form.getlist("oid"), form.getlist("option"))` 按位置配对，新增选项行必须同时带一个空的 `oid` 隐藏字段，否则新选项会被静默丢弃。

结论：缺陷**仅在网页层**；接口层本就支持任意数量选项。

## 交付

- 「添加题目」表单提供「添加选项」控件，可增加到 5 个以上选项。
- 每道已存题目的编辑表单也提供「添加选项」控件；新增行的 `oid` 隐藏字段留空，由服务端分配稳定标识。
- 空白选项行在提交时仍被丢弃（既有行为，需回归确认）。
- 更新 `docs/acceptance-web.md` 的单选示范为 3 个选项（关系型数据库 / 文档数据库 / 图数据库）。

## 测试

- HTTP 层：以表单编码提交 5 个选项，题目应有的 5 个选项（证明服务端契约）。
- HTTP 层：编辑题目时追加一行新选项（空 oid），提交后选项数增加且原选项的 oid 不变。
- 页面层：新增题目表单与编辑表单都出现「添加选项」控件。
- 空白选项行不产生空选项。

## 验收条件

- [ ] 网页上能创建含 3 个及以上选项的单选 / 多选题目。
- [ ] 编辑已有题目时能新增选项，且原有选项的稳定标识不改变。
- [ ] 空白选项行不会产生空选项。
- [ ] `docs/acceptance-web.md` 的示范使用 3 个选项。
- [ ] 既有 203 例测试全部通过，不回落。

## Comments

- 2026-10-17：主控在浏览器验收前置检查中质疑「选项数量没有上限」，经核对 `survey_edit.html` 确认网页层写死两个输入框，缺陷成立。此前关于「想加 5 个、10 个都行」的表述有误，已更正。
